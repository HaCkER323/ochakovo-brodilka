# QA test plan — «БРОДИЛКА» PWA (квас / лимонады)

**Задача:** task-4 (QA-стенд и тест-план) → далее task-5 (финальная регрессия).
**Статус документа:** актуален для новой версии (PWA про квас/лимонады, без пива). Production-код переделывается другими агентами; результаты прогонов на старой сборке в этот план не входят и финальными багами не считаются.
**Зона QA:** `ochakovo-brodilka/qa-report/**` (production не меняется).

## 1. Что проверяем

Статический мини-сайт-квест, который после переделки должен стать устанавливаемым мобильным PWA:

- лендинг → интро → выбор героя → три маршрута → финал → смена героя;
- мини-игры: рецепт/выбор, сортировка, поиск брака, pH, пробы, рабочие решения (набор и названия могут измениться под квас/лимонады — проверяется фактический набор из `js/data.js`);
- приз: промокод, копирование, звёзды точности;
- форма отклика: пустая/невалидная/валидная отправка, скачивание заявки;
- сохранение прогресса, reload/продолжение, сброс, модалка;
- клавиатура и фокус, звук, отсутствие горизонтального скролла и ошибок консоли;
- PWA: манифест, установка/standalone, service worker, offline reload, кэш, иконки, safe-area, iOS meta.

## 2. Стенд и артефакты

| Компонент | Путь | Назначение |
|---|---|---|
| Тест-план | `qa-report/test-plan.md` | этот файл |
| CDP-раннер | `qa-report/run-qa.js` | сквозной прогон, скриншоты, сбор консоли/сети, PWA-проверки (Node ≥ 22, без npm-пакетов) |
| Статический сервер | встроен в `run-qa.js` | http://127.0.0.1:\<port\>, нужен для PWA/SW |
| Скриншоты | `qa-report/screens/<scenario>/` | доказательства, создаются прогоном (в поставку не входят) |
| Машинный отчёт | `qa-report/artifacts/latest.json` | статусы проверок, ошибки, метрики |
| Итоговый отчёт регрессии | `qa-report/final-v4.md` | матрица, баги P0–P2, шаги, expected/actual, verdict v15 |

Запуск:

```powershell
# полный прогон (все сценарии, автоматически поднимает http-сервер)
node qa-report/run-qa.js

# быстрый smoke (лендинг/интро/выбор героя, 1440×1000)
node qa-report/run-qa.js --scenario=survey-desktop

# список сценариев / запуск подмножества
node qa-report/run-qa.js --list
node qa-report/run-qa.js --scenario=desktop-full,mobile-reload,pwa

# свой сервер и/или браузер
node qa-report/run-qa.js --url=http://127.0.0.1:8080 --browser="C:\...\msedge.exe"
```

Требования: Node.js 22+ (встроенный `WebSocket`), Edge или Chrome, свободный localhost-порт. Внешние CDN не используются.

## 5. Детальные проверки

### A. Лендинг и интро
- [ ] A1 Лендинг рендерится без пустых блоков, CTA «Начать смену» кликабельна, ведёт в интро при первом входе.
- [ ] A2 При повторном входе с сохранённым прогрессом CTA = «Продолжить смену», показывает героя и этап.
- [ ] A3 Все иллюстрации/иконки загружаются (нет 404, нет `alt=""` у смысловых изображений).
- [ ] A4 Интро: 5 шагов (или фактическое число), счётчик и прогресс совпадают, «Дальше» на последнем шаге = «Выбрать героя».
- [ ] A5 Skip интро сразу открывает выбор героя, `introSeen` сохраняется.
- [ ] A6 Enter на интро переключает шаги; Enter не срабатывает, когда фокус на кнопке.
- [ ] A7 Интро не блокирует игру при повторном прохождении (после сброса показывается снова).

### B. Маршруты и мини-игры
Для каждого из трёх героев:
- [ ] B1 Диалог: все реплики доступны, «Дальше»/«К заданию» работает, счётчик этапа верный.
- [ ] B2 Мини-игра 1: корректная победа; при ошибке — понятный фидбек, попытка не теряет прогресс, звёзды снижаются.
- [ ] B3 Мини-игра 2: то же; проверены крайние состояния виджета (лимит выбора, disabled, reset, таймер).
- [ ] B4 Мини-игра 3: то же; проверена финальная кнопка этапа.
- [ ] B5 Таймерные механики: успех до дедлайна, обработка таймаута, повтор раунда, отсутствие зависания после таймаута.
- [ ] B6 «Назад на карту» ставит смену на паузу, прогресс этапа сохраняется; возврат продолжает с того же места.
- [ ] B7 Смена героя посреди маршрута: модалка предупреждения, «Остаться» сохраняет прогресс, «Начать новую» сбрасывает активную смену.
- [ ] B8 После 3/3 этапов — финал, `completed[charId]` сохраняется, повторное прохождение не дублирует награду.

### C. Приз и результат
- [ ] C1 Промокод отображается, формат стабилен (напр. `OCHK-XXXX`), не пустой.
- [ ] C2 «Копировать» показывает тост об успехе/ручном копировании, код попадает в clipboard (в secure context).
- [ ] C3 Звёзды точности: 3/3 при чистом прохождении, снижение при ошибке, отображение в HUD/результате/карточке героя.
- [ ] C4 «Поделиться» не роняет страницу (Web Share API или fallback-копирование).
- [ ] C5 «Другая история» ведёт на выбор героя, результат и заявка не теряются.
- [ ] C6 После трёх смен — состояние «3 из 3», повторный проход доступен.

### D. Форма отклика
- [ ] D1 Пустая отправка: подсветка name/phone/email, чекбокс согласия, общий текст ошибки, фокус на первом невалидном поле.
- [ ] D2 Невалидные значения: имя 1 символ, телефон < 10 цифр, email без домена, ссылка без `http(s)`, невалидный файл > 8 МБ — каждая ошибка видна и привязана к полю.
- [ ] D3 Ошибка поля исчезает при вводе; общая ошибка сбрасывается.
- [ ] D4 Нельзя отправить без согласия; сообщение объясняет причину.
- [ ] D5 Валидные данные → состояние успеха, номер заявки, заявка в `localStorage`, счётчик/статус у HR.
- [ ] D6 Скачивание заявки: файл создаётся, имя содержит номер, содержимое соответствует введённым данным.
- [ ] D7 Повторная отправка не дублирует заявку молча; результат помечает «Заявка у HR».
- [ ] D8 Ошибка сети/вебхука: сообщение об ошибке, кнопка снова активна, данные не теряются (проверить с подменённым `applyEndpoint`, если он задан).
- [ ] D9 На мобиле клавиатура/скролл не перекрывают поля и кнопку submit.

### E. Сохранение, reload, сброс
- [ ] E1 Релоад посреди смены: лендинг показывает «Продолжить смену», возврат в игру на тот же этап/фазу.
- [ ] E2 Релоад после завершения: прогресс, промокоды, заявки сохраняются; повторный вход не теряет звёзды.
- [ ] E3 Сброс: модалка с предупреждением; Esc/«Остаться» ничего не удаляет; «Сбросить» очищает прогресс, заявки, звёзды, `localStorage`.
- [ ] E4 Повреждённый `localStorage` (невалидный JSON/старая версия) не роняет приложение — чистый старт.
- [ ] E5 `localStorage` недоступен (private mode) — игра работает без падения.

### F. Клавиатура и доступность
- [ ] F1 Skip-link первым Tab появляется и ведёт к игре.
- [ ] F2 Enter на интро и в диалогах продвигает вперёд, не конфликтует с фокусом на кнопках.
- [ ] F3 Esc закрывает модалку; фокус возвращается на элемент-инициатор.
