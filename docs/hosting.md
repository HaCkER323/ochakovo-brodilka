# Хостинг, отклики и скрытая админка

## Что уже работает

- Фронтенд статический: сборки нет, пути относительные, PWA и офлайн работают по HTTPS.
- `serve.js` поднимает сайт, API и админку на одном Node-процессе.
- Карточки уходят на `POST /api/applications` и лежат в `data/applications.json`.
- Админка: `/admin`. Ссылки на неё в интерфейсе нет, страница закрыта паролем и `noindex`.
- Пароль задаётся переменной `ADMIN_PASSWORD`. Если её нет, при первом запуске создаётся `.admin-password`, а пароль печатается в консоль.
- В админке только количество, предпоказ последних шести откликов и выгрузка всех в Excel с удалением выгруженных. Никаких фильтров, редактирования и точечных удалений.
- Отклики и пароль не попадают в git: `data/` и `.admin-password` в `.gitignore`.

Локальный запуск:

```powershell
$env:ADMIN_PASSWORD = "свой-пароль"
node serve.js
```

Сайт: `http://127.0.0.1:4173/`  
Админка: `http://127.0.0.1:4173/admin`

## Куда хостить

| Вариант | Подходит | Нюансы |
|---|---|---|
| Node-хостинг: Railway, Render, VPS | сайт + отклики + админка | нужен постоянный диск для `data/`, HTTPS и переменные окружения |
| Cloudflare Pages + Pages Functions + D1 | если нужен serverless | текущий `serve.js` туда не переносится один в один, нужна адаптация |
| Netlify/Vercel + Functions | аналогично | нужен отдельный API и база |
| GitHub Pages / обычный static | только игра без сбора откликов | `/api` и `/admin` работать не будут |

Для текущей реализации проще всего Render/Railway/VPS: один Node-процесс, постоянный диск, reverse proxy с HTTPS.

### Переменные окружения

- `ADMIN_PASSWORD` — пароль админки. Обязателен для публичного демо.
- `SESSION_SECRET` — секрет подписи cookie. Если не задан, генерируется при старте, и после рестарта админка разлогинится.
- `PORT` — порт, по умолчанию 4173.
- `HOST` — интерфейс, для контейнера `0.0.0.0`.

### Постоянный диск

`data/applications.json` должен переживать рестарт. На Render/Railway подключи persistent disk и положи туда `data/`. На VPS просто не удаляй папку.

Один процесс и один JSON-файл — это демо. Для нескольких инстансов, большой нагрузки и нормальной аналитики нужна база: Postgres, SQLite с блокировками или Cloudflare D1.

## Скрытая страница

`/admin` не индексируется и не имеет ссылок с сайта. Внутри:

1. Вход по паролю, cookie HttpOnly + SameSite=Strict, лимит попыток.
2. Количество откликов.
3. Шесть последних карточек для быстрого взгляда.
4. Кнопка выгрузки всего в Excel. После успешной отдачи файла сервер удаляет именно те записи, которые попали в выгрузку.

Если в момент экспорта придёт новая заявка, она не попадёт в файл и не будет удалена. Это сделано специально.

## Внешние сервисы вместо своего сервера

Если не хочется держать Node:

- Formspree, Web3Forms, Getform: быстро, письмо на почту, но нет нормальной админки и общего списка.
- Cloudflare Pages Function + D1 + Resend: свой endpoint, база и письмо. Нужно переписать API под Workers.
- Supabase: таблица и Edge Function, админка через Dashboard или magic-link.

В любом варианте форма отправляет JSON: `name` (ФИО), `birthDate`, `education`, `phone`, `email`, `city`, `resumeLink`, `consent`, `vacancy`, `charId`, `source`.

## Файл резюме

Сейчас форма просит только ссылку, файл не нужен. Если появится загрузка:

- R2/S3 с presigned URL;
- хранить ссылку, а не base64 в JSON;
- ограничить размер и тип (PDF/DOCX);
- отдельно описать срок хранения и удаление.

## Перед публичным демо

1. Поднять Node-процесс, HTTPS и постоянный диск.
2. Задать `ADMIN_PASSWORD` и `SESSION_SECRET`.
3. Сделать тестовую заявку, проверить админку и Excel.
4. Проверить, что после экспорта счётчик стал 0.
5. Проверить установку PWA на телефоне.
6. Написать политику хранения персональных данных.
7. Сделать резервную копию `data/applications.json`.
