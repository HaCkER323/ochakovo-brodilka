# Хостинг и куда отправлять заявки

Проект статический: сборки нет, все пути относительные, `start_url` и `scope` в манифесте уже `./`. Для PWA нужен HTTPS — на `file://` service worker и установка не работают.

## Что уже готово к хостингу

- Нет сборки и зависимостей: заливаешь папку `ochakovo-brodilka/` как есть.
- Относительные пути к ассетам, CSS и JS.
- `manifest.webmanifest`, `sw.js`, иконки 192/512/maskable.
- Роутинг без смены URL: `pushState` пишет только `history.state`, поэтому fallback на `index.html` для глубоких ссылок не нужен.
- Форма «Карточка стажёра» отправляет `name` (ФИО), `birthDate`, `education`, `phone`, `email`, `city`, `resumeLink` и `consent`. Endpoint задаётся в `js/config.js`; без него данные остаются в `localStorage`.

## Варианты хостинга

| Хостинг | Плюсы | Нюансы |
|---|---|---|
| Cloudflare Pages | бесплатный HTTPS, быстрый CDN, Pages Functions для формы, D1/KV | нужно выбрать аккаунт и домен |
| Netlify | drag-and-drop папки, формы, Functions | бесплатный лимит заявок |
| Vercel | быстрый деплой, serverless functions | для статики избыточен |
| GitHub Pages | уже есть репозиторий | только статика, формам нужен внешний сервис |

Для демо быстрее всего Cloudflare Pages или Netlify: залить папку, включить HTTPS, проверить установку PWA на телефон.

## Куда отправлять заявку

### Вариант 1. Готовый form-сервис

Formspree, Web3Forms или Getform. В `js/config.js`:

```js
window.BRODILKA_CONFIG = {
  applyEndpoint: "https://formspree.io/f/XXXXXX"
};
```

Письмо с заявкой приходит на почту. Плюс: делается за вечер, без своего бэкенда. Минус: нет нормальной админки, вложения и антиспам ограничены, бесплатный тариф шлёт ограниченное число заявок.

### Вариант 2. Cloudflare Pages Function + D1 + Resend

Свой endpoint `/api/apply`, который:

1. принимает JSON заявки;
2. проверяет обязательные поля и honeypot/Turnstile;
3. пишет запись в D1 (SQLite);
4. отправляет письмо через Resend или MailChannels;
5. отдаёт номер заявки.

Плюсы: заявки не теряются, можно сделать закрытую админку, видеть историю и статусы. Минус: нужен аккаунт Cloudflare и 1–2 часа на настройку.

### Вариант 3. Supabase

Таблица `applications`, Edge Function для приёма, RLS. Админка — Supabase Dashboard или отдельная страница с magic-link. Быстро, но для демо всё равно нужен аккаунт и ключи.

## Про «стелс-страницу»

Отдельная страница на статическом хостинге не даст доступа к заявкам других людей: у каждого свой `localStorage`. Если делать админку, то только поверх базы:

- `/admin` с Cloudflare Access (Google/почта) — самый простой безопасный вариант;
- либо `/admin?token=...` с секретом в переменной окружения, но токен в URL — компромисс для демо;
- страница показывает только номер, вакансию, дату и статус; телефон/почту раскрывать по кнопке.

Не хранить персональные данные в открытом репозитории и не отдавать админку без авторизации.

## Файл резюме

Сейчас форма специально просит только ссылку — файл не нужен. Если позже понадобится загрузка:

- Cloudflare R2 или S3 с presigned URL;
- хранить ссылку на файл, а не base64 в localStorage;
- ограничить размер, тип (PDF/DOCX) и срок хранения;
- отдельно согласовать удаление данных.

## Что стоит сделать перед публичным демо

1. Выбрать хостинг и подключить HTTPS.
2. Поднять endpoint и заполнить `applyEndpoint`.
3. Добавить honeypot/Turnstile и лимит запросов.
4. Проверить мобильную установку PWA на реальном телефоне.
5. Написать политику хранения заявок и согласие на обработку.
6. Сделать тестовую заявку и убедиться, что письмо/запись дошла.

Пока endpoint пустой, форма честно пишет «сохранено в браузере» — это нормальный демо-режим, но не для сбора реальных резюме.
